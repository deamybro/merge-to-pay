Merge it.
Prove it. Get paid.

Merge-to-Pay is an agent that pays GitHub bounties in USDC on Base, and only after zkVerify has verified a zero-knowledge proof that GitHub itself reported the pull request as merged. No maintainer has to press "pay", and nobody has to trust the agent.

Run the agent

Give it any public GitHub pull request. It proves what api.github.com returned, verifies that proof on zkVerify mainnet, and pays if a funded bounty matches.

To claim a bounty, the PR description must start with verity-payout: #<issue> 0x<your Base address>. Results for a merged PR are permanent and shown again on later requests.

    How it works

    Five steps from merge to money. The agent never holds the bounty and cannot choose who gets paid.

    FundA maintainer locks USDC in the escrow for one issue, with an expiry and the first PR number allowed to claim it.
    zkTLSOur attestor witnesses a real TLS session with api.github.com and signs what GitHub returned: merged_at and the payout line.
    CircuitA Noir circuit checks the attestor's signature over that response and outputs 7 public facts: attestor, repo, PR, merged, issue, payee, time.
    zkVerifyThe UltraHonk proof is verified on zkVerify mainnet through Kurier, then aggregated and published on Base.
    PayThe escrow checks the aggregation on Base and pays the payee fixed by the proof. The agent sends the transaction, but anyone could.
